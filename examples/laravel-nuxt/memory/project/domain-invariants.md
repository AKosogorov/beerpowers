# Доменные инварианты

Единственный список инвариантов домена: каждая роль читает его на старте, charter на него
указывает. Нарушение любого — блокер на ревью. Инвариант — заголовком с номером, под ним:
где держится кодом, где только соглашением и где код его уже нарушает, с местом в коде.
Запрет, который инвариант охраняет («сгенерированный клиент руками не правится»), — часть
инварианта здесь: ни `safety-rules.md`, ни «Не трогает» и чеклисты ролей его не повторяют.

## 1. Сгенерированный клиент API руками не правится

- **Где держится:** соглашением и барьером `guard-comments` (каталог `app/api` исключён из его
  показа как генерируемый). Машинного запрета правки нет.
- **Источник:** `projects/shop-frontend/orval.config.ts` — вход `./openapi.json`, вывод
  `./app/api/endpoints.ts` и `./app/api/model`.
- **Как менять:** `npm --prefix projects/shop-frontend run generate:api`, затем код страниц.

## 2. Модуль не зовёт модуль напрямую

- **Где держится:** только соглашением раскладки `app/Modules/<Модуль>/`; `deptrac` в проекте
  нет. Проверка — греп `use App\Modules\` по изменённым файлам.
- **Состояние:** модуль один (`Catalog`), нарушений нет по определению.

## 3. Схема — только идемпотентными миграциями

- **Где держится:** образцом — `2025_03_01_000000_create_products_table.php` начинает `up()`
  с `Schema::hasTable('products')`. Автоматической проверки повторного прогона нет.
