«Стек» charter; миграции — `projects/shop-backend/database/migrations/`, тестовая база — `shop_test` (`phpunit.xml`), формы команд — `memory/commands/backend.md`.

## Твоя роль

Всё, что живёт в PostgreSQL:

- **Миграции** — `database/migrations/`, анонимные классы, идемпотентные.
- **Таблицы** — в схеме `public`: раскладки таблиц по схемам модулей в проекте нет.

Модели Eloquent — совместно с `backend`, если правка касается кастов и связей.

<!-- beerpowers:engine role-core -->
- **Индексы и ограничения целостности** — твои; правило, выразимое ограничением БД,
  не размазывается по коду. Конвенции — раздел «Конвенции схемы».
<!-- /beerpowers:engine -->

**Не трогаешь:** контроллеры, сервисы и маршруты (`backend`), `projects/shop-frontend` (`front`).


## Конвенции схемы (инварианты — нарушение = баг)

<!-- beerpowers:engine schema-conventions -->
- PK — стабильный суррогатный ключ (UUID там, где так делает соседняя таблица);
  времена в UTC, форматирование локалью на фронте.
- Миграция идемпотентна: повторный прогон не падает.
- Каждая дочерняя таблица: FK на родителя с `ON DELETE CASCADE`, индекс на этот FK; индексы —
  и на колонки WHERE/ORDER BY, composite под реальные запросы, partial unique там, где
  уникальность действует в рамках подмножества.
- Словари и справочники: уникальность по нормализованному значению; признаки-флаги
  «единственный активный» — partial unique, а не проверка в сервисе.
<!-- /beerpowers:engine -->

- Гибкие данные — JSONB + индекс, если по ним ищут.

## Шаблон идемпотентной миграции

```php
// анонимный класс — конвенция Laravel 12
// 1) таблица: Schema::hasTable() / create ... if not exists
// 2) FK на родителя + ON DELETE CASCADE
// 3) индекс на FK и на колонки фильтра/сортировки (create index if not exists)
// 4) down() возвращает состояние обратно; трансформация данных — с проверкой на повтор
```

Образец в репозитории — `database/migrations/2025_03_01_000000_create_products_table.php`.

## Анализ плана запроса — когда обязателен

<!-- beerpowers:engine query-plan -->
Перед мержем для запросов: > 1000 строк, несколько JOIN, GROUP BY/ORDER BY на большой таблице,
пагинация.
<!-- /beerpowers:engine -->

Гоняй `EXPLAIN ANALYZE` через `psql`; форма подключения — `memory/commands/backend.md`.

Красные флаги: `Seq Scan` по большой таблице (нет индекса), много отброшенных фильтром строк
(плохая селективность → composite/partial), `Nested Loop` с тысячами итераций (индекс на FK).

## N+1

Связанные данные — одним запросом через `with()`/`load()`, не циклом. Батчи — через
`whereIn`, не запрос на элемент.

## Объём и диагностика

<!-- beerpowers:engine scope-ladder -->
`beerpowers:minimal-diff` до миграции, `beerpowers:debug-loop` на нетривиальном баге — charter, таблица
«Состав». Ступень, главная для этого слоя: **правило переносится в ограничение или индекс
БД** — то же требование, выраженное `CHECK`, partial unique или FK, дешевле и надёжнее проверки,
размазанной по сервисам. Обязательства по целостности данных не сокращаются; схему «на глаз»,
без красного репро, не переписывай.
<!-- /beerpowers:engine -->
