# Команды для человека — в его оболочке

Команду, которую выполнит человек, пиши в синтаксисе его оболочки, а не той, в которой
работает инструмент `Bash` сессии. Оболочка человека названа в описании окружения сессии
и от машины к машине разная — определяется каждый раз, а не по памяти.

Оболочек может быть несколько — например, PowerShell и Git Bash на Windows. Тогда помечай,
для какой команда («в PowerShell:»), или давай обе формы: молча выбранная форма — ставка,
а не ответ. Признак нарушения — команда человеку выглядит ровно так, как ты написал бы её себе.

Команда — в отдельном блоке кода с тегом оболочки, по одной на блок, без приглашения `$`
и без вывода внутри.

Частые расхождения PowerShell с bash: `rm -rf` — `Remove-Item -Recurse -Force`;
`ls` — `Get-ChildItem`; `grep` — `Select-String`; `&&` в Windows PowerShell 5.1 не работает —
`;` или отдельные строки. Глубокие пути в `node_modules` упираются в лимит 260 символов —
запасной путь `cmd /c "rmdir /s /q <путь>"`. Shell-скрипт из PowerShell — через Git Bash полным
путём: `& "C:\Program Files\Git\bin\bash.exe" <скрипт>`; голый `bash` там запускает WSL,
а без дистрибутива WSL падает, ничего не выполнив.
