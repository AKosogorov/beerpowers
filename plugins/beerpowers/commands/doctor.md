# /beerpowers:doctor — самодиагностика

> Читает только team-lead. Диагностика: таблица pass / warn / fail с фиксом на каждую строку.
> Сам ничего не меняет, кроме мелких безопасных фиксов по согласию пользователя (раздел
> «Вывод»). Запускай при «что-то не работает», после обновления Claude Code, при онбординге
> коллеги и на второй машине. Плагин обновился — сначала [`/beerpowers:update`](update.md),
> он переносит новую версию в проект; doctor потом подтверждает, что всё зелёное.
> Контракт параметров, engine-блоков и копий — [`../reference/workspace.md`](../reference/workspace.md).

**Команды проверок — простыми вызовами.** Один вызов — одна команда или короткая цепочка без
подстановки `$(…)` и без переменной в имени команды: такую форму разрешение пропускает, а составную
с подстановкой запрос разрешения может отклонить. Путь плагина — как он дан (`D:/…` на Windows):
`node` под Windows путь вида `/d/…` не находит, и проверка падает ложно. Отказ в разрешении —
не повод завернуть те же команды в скрипт и запустить его: это обход решения человека. Разбей
проверку на простые вызовы или спроси пользователя; причину отказа называй по тексту отказа,
а не догадкой.

15. **Машина** — всё установленное запускается здесь, а не только лежит на диске. Прогоняется

    а окружение — нет. Каждая строка — pass/fail с командой, которой проверено:

      shebang, и отсутствующий интерпретатор, и CRLF в копии;
    - исполняемый бит: `git ls-files -s .claude/bin .claude/hooks` — у shell-скриптов `100755`
      (**fail** иначе: на macOS и Linux хук и скрипт без бита не запускаются, на Windows это
      незаметно); фикс — `git update-index --chmod=+x <файл>`;

      `.claude/settings.local.json` (не в `workspace.json`: путь у каждой машины свой);

      кончается кодом 0: маски находят файлы, переменные `{env:…}` на этой машине заданы

      [`../reference/parallel-tests.md`](../reference/parallel-tests.md)); в выводе — лимит
      слотов и откуда он; лимит выше числа ядер машины — **warn**;
    - есть `tests.repos.<репо>.mutate` — каталоги `mutate.link` и файлы `mutate.copy` есть
      в `projects/<репо>` (**fail** иначе: копия мутанта не соберётся), файл `mutate.copy` не
      отслеживается git (**fail** иначе: `git -C projects/<репо> ls-files <файл>` непуст); копия в
      `.claude/.cache/mutants/` репозитория без `mutate` — **warn** с фиксом
      `node .claude/bin/mutants.mjs --clean`;

      настройках есть (значение не печатать, только факт наличия);
    - личные переменные из `env` файла `.claude/settings.local.json`, которые указывают на файл
      (`BEERPOWERS_CHROME`), указывают на существующий.

## Вывод

Таблица: пункт · статус · что именно не так · конкретный фикс (команда или правка файла).
После таблицы предложи применить **безопасные** фиксы (создание недостающих `MEMORY.md`
и каталогов памяти, формат `deny`-правил, недостающие правила `allow` для копий плагина,
кроме адаптера записи в трекер — ему маски по командам) — по подтверждению пользователя, по одному классу за раз. Ничего не удаляй сам;
сомнительное — только показывай.

Не входят в безопасные фиксы: копии и engine-блоки (п. 3, 6) — их чинит `/beerpowers:update`
с показом диффа; навыки (п. 13) — `name-only` меняет settings пользователя, а удаление из
колонки — контракт команды; состав (п. 14) — роли добавляет и убирает пользователь через
`/beerpowers:setup`.
