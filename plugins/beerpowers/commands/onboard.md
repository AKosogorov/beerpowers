# /beerpowers:onboard — глубокий онбординг памяти

> Читает только team-lead. Setup делает быстрый discovery (5-10 tool calls) — этого хватает для
> charter, но `memory/` рождается тощей. Onboard — отдельный глубокий проход, чтобы команда
> не была «слепой» первые эпики. Когда: сразу после `/beerpowers:setup` на существующей кодовой базе
> или позже, когда память ощутимо отстаёт от кода. Для greenfield-проекта не нужен.
> Продуктовая линза (разделы/акторы/словарь/аналитика глазами пользователя) — отдельная команда
> [`/beerpowers:product-onboard`](product-onboard.md).

## Шаги

1. **Инвентаризация.** Прочитай charter (если есть) и текущее `memory/` — что уже записано,
   дубликаты не создавать. Составь список подсистем для исследования: слои из discovery
   (фронт-модули, серверные routes, схема БД и миграции, realtime, инфра/CI) + крупные каталоги.
2. **План и подтверждение объёма.** Покажи список исследователей (подсистема → что ищем)
   и объём (N параллельных агентов). Fan-out жжёт токены — дождись ok пользователя.
3. **Fan-out (режим C — параллельные `Agent`, НЕ Workflow).** На подсистему — `Explore` /
   `general-purpose` с чётким заданием:
   - точки входа и карта модуля;
   - реальные конвенции (именование, паттерны) с прецедентами `file:line`;
   - инварианты, **соблюдаемые кодом** (не желаемые): владение данными, каскады, проверки
     доступа, переходы состояний;
   - известные грабли (TODO/FIXME/workaround-комментарии, подозрительные обходы).
   Исследователь возвращает структурированный ВЫВОД — в память сам не пишет.
4. **Синтез (team-lead).** Сведи отчёты в файлы `memory/` по раскладке по виду знания —
   адрес каждой находки по таблице «Куда класть находку» в `memory/MEMORY.md`:
   - карта и точки входа → `project/project-map.md`; устройство слоя → `project/<слой>.md`,
     модуля → `project/modules/<модуль>.md`; схема БД → `project/db-schema.md`;
   - словарь домена → `project/glossary.md`; инварианты → `project/domain-invariants.md` (единственный список,
     charter на него указывает);
   - формы команд и грабли инструментов → `commands/<скоуп>.md` и строка в `commands/README.md`;
   - грабли кода → `issues/<область>.md` и строка в индексе `issues/known-issues.md`
     (новый файл области — при трёх записях);
   - недостаток с планом починки → `tech-debt/NNN-<slug>.md`, затем
     `node .claude/bin/tech-debt-index.mjs`;
   - конвенции тестов → `tests/backend.md` / `tests/frontend.md`; утверждения без прогона →
     `tests/unverified.md`;
   - при `ui: true` — брейкпоинты вёрстки с `file:line` (исследователь фронта ищет их
     в конфиге Tailwind или UI-кита, SCSS-переменных, `@media`) сверяются с `viewports`
     в `.claude/workspace.json` по правилу из `reference/workspace.md` плагина, абзац «Viewports».
     Расхождение — диапазон без записи, запись без диапазона, ширина не на границе — показать
     пользователю таблицей и поправить `workspace.json` по его ответу; раздел «Брейкпоинты»
     в `tests/frontend.md` обновить.
   Конфликт между отчётами — проверь сам по коду. Каждый инвариант — с прецедентом
   `file:line`; гипотезы помечай как гипотезы.
5. **Индекс и отчёт.** Обнови `MEMORY.md` (строка на новый файл; раздел «Белые пятна — что не разбиралось» — создать, если его нет) и прогони
   `node .claude/bin/workspace-check.mjs` — битые ссылки и файлы вне раскладки ловит он.
   Пользователю — что записано и что осталось белым пятном (кандидаты на следующий проход).
6. **Закрой окно барьера** последним вызовом: `sh "${CLAUDE_PLUGIN_ROOT}/hooks/guard-user-files.sh" --close`.

## Правила

- Исследователи read-only: код не правят, в память не пишут — пишет только team-lead
  (контроль дублей и качества).
- Не дублировать CLAUDE.md/README — память дополняет их, не пересказывает.
- Существующую память дополнять через `Edit`, а не переписывать: в ней записи людей
  и прошлых задач, которых исследователи не видят. Запись, противоречащую коду, не удалять
  молча — показать пользователю с прецедентом `file:line`. Заменить существующий файл
  целиком или удалить его не даст барьер `guard-user-files` плагина, пока идёт команда.
- Инвариант без подтверждения в коде инвариантом не записывается.
- Объём: файлы памяти — сжатые факты, не эссе; глубокие детали — отдельными topic-файлами
  со ссылкой из `MEMORY.md`.
- Очень большой репозиторий — итерациями: ядро сейчас, периферия следующим проходом.
