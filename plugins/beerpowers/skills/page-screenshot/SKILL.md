# Браузер и скриншот страницы файлом

## Какой браузер для чего

**Браузер пользователя — только своей вкладкой и без уборки.** В Chrome человека его
вкладки и живые сессии, поэтому работа в нём идёт строго в своей вкладке, созданной
`tabs_create_mcp`, с её `tabId` в каждом вызове. Вкладки не закрываются — инструмент
закрытия ролям не выдан намеренно, своя вкладка остаётся открытой. Сам Chrome не гасится
ничем, ни по имени, ни по PID. Годится он для интерактива: клики, ввод, переходы, чтение
консоли и network.

**Скриншот на диск умеет только свой headless Chrome.** Инструменты браузера скриншот файлом
не пишут: `mcp__claude-in-chrome__computer` с `save_to_disk: true` возвращает идентификатор
снимка и на диск ничего не кладёт, а встроенный `mcp__Claude_Browser__*` отдаёт снимок только
в контекст. Для всего, где файл не нужен, — прокликать, прочитать DOM, снять консоль
и network — встроенный годится.

**Ширины прогона — список `viewports` проекта**, а не привычная пара mobile и desktop:
запись на каждый диапазон вёрстки, который проект поддерживает; откуда взяты брейкпоинты —
`memory/tests/frontend.md`, раздел «Брейкпоинты». Затронутый экран проверяется **на каждой
записи списка — и в self-check `front`, и в прогоне `tester`**: роль, проверившая меньше
ширин, сдаёт экран, который следующая вернёт с дефектом на пропущенной, и задача ходит
по кругу.

**Имя скриншота — `<роль>-<экран>-<ширина>.png`**: `front-` у self-check, `tester-` у прогона,
падение — суффикс `-FAIL`. Роль в имени обязательна: гейт скриншотов финального `reviewer`'а
закрывают только скриншоты `tester-*`.

Скрипт — `.claude/bin/cdp-screenshot.mjs` проекта, каталог скриншотов задачи —
`memory/tasks/<КОД>/screenshots/`.

## Порядок

**1. Поднять свой Chrome.** Порт отладки выбирается свободный — 9333 бывает занят соседней
ролью, и тогда скрипт подключится к чужому браузеру. Каталог профиля — свой, в scratchpad.

```bash
CDP_PORT=9401 node .claude/bin/cdp-screenshot.mjs --launch <scratchpad>/chrome-page-screenshot
```

Скрипт сам находит Chrome на этой машине (стандартные места установки под ОС, затем
Chromium и Edge; личный путь — переменная `BEERPOWERS_CHROME` в `env` файла
`.claude/settings.local.json`), ждёт, пока порт ответит, и печатает `pid=… port=…` — PID
запомни. Порт занят чужим браузером — отказ, выбери другой. Где Chrome на этой машине —
`node .claude/bin/cdp-screenshot.mjs --find-chrome`.

**2. Снять скриншоты и метрики.** Сценарии передаются JSON-массивом одним аргументом:

```bash
SCREENSHOT_TASK=<КОД> CDP_PORT=9401 node .claude/bin/cdp-screenshot.mjs '[{"url":"http://localhost:<порт>/","viewport":"desktop","out":"tester-cart-1440.png"}]'
```

Список ширин печатает `node .claude/bin/cdp-screenshot.mjs --viewports`. Поле `viewport` берёт
из записи `width`, `height` и `mobile`; без него `width` и `height` обязательны. Остальные поля:
`url` обязателен; `mobile` включает эмуляцию устройства,
`waitMs` задаёт паузу после `load` (по умолчанию 2000), `out` — путь скриншота (не задан — скриншот
не снимается, только метрики), `fullPage` снимает страницу целиком, `probe` — выражение
JavaScript, результат которого попадёт в отчёт полем `metrics`.

**Куда ложатся скриншоты.** Скриншоты прогонов задачи живут в `memory/tasks/<КОД>/screenshots/` —
каталог под gitignore внутри папки задачи. Переменная `SCREENSHOT_TASK=<КОД>` направляет туда
каждый относительный `out` (в примере выше скриншот ляжет в
`memory/tasks/<КОД>/screenshots/tester-cart-1440.png`); каталог `screenshots/` скрипт создаёт сам,
папка задачи должна уже существовать. Код задачи в имени файла не нужен — его несёт каталог;
имя говорит, кто снял и что: роль, экран, ширина. Абсолютный `out` берётся как есть,
без `SCREENSHOT_TASK` относительный считается от текущего каталога. Убираются скриншоты вместе
с задачей: `.claude/bin/workspace-clean task <КОД>`.

Скрипт печатает `targetId` и `sessionId` каждой вкладки плюс версию браузера и порт. Эти
идентификаторы нужны, когда скриншоты расходятся между заходами и надо сослаться на конкретный
прогон: восстановить их потом неоткуда.

**3. Убрать за собой.** Chrome закрывается штатной командой протокола `Browser.close`:

```bash
CDP_PORT=9401 node .claude/bin/cdp-screenshot.mjs --close
```

Скрипт ждёт, пока порт перестанет отвечать, и говорит «закрыт» — это и есть проверка.

`taskkill //F //PID <pid> //T` на Chrome выходит по таймауту, не закрыв браузер: дерево
процессов Chrome переживает сигнал. Гасить по имени образа нельзя ни в каком случае —
`taskkill //IM chrome.exe` снесёт и браузер пользователя, поэтому форма заблокирована
барьером `guard-kill`. Если `Browser.close` не сработал — процесс гасится по PID, который
напечатал `--launch`: на Windows `Stop-Process -Id <pid> -Force` в PowerShell (дерево Chrome
сигнал `taskkill` переживает), на macOS и Linux — `kill <pid>`.

## Ловушки

**Скриншот без прогрева снимается раньше кода страницы.** `chrome --headless --screenshot` без
`--virtual-time-budget` делает снимок по событию `load`, до того как отработает логика
монтирования компонента. Лента прокрутки на таком скриншоте выглядит непрокрученной, хотя
фактически сдвинута. Скрипт этого скилла ждёт `waitMs` после `load` именно поэтому.

**Положение прокрутки, фокус и результат отложенного эффекта читаются свойством, а не
глазами по скриншоту.** Для этого и нужен `probe`: `scrollLeft`, `scrollWidth`, `clientWidth`,
`getComputedStyle`, `getBoundingClientRect`. Скриншот годится для вёрстки, цвета и композиции.

**Скрытая копия узла попадает в выборку.** Если раскладка держит два экземпляра блока под
разные ширины, `querySelectorAll` вернёт оба, и невидимый даст нулевые размеры. Селекторы
в `probe` фильтруются по видимости, иначе замер соврёт.

**Состояние из `localStorage` требует предзаписи.** Скрипт поднимает Chrome со своим
каталогом профиля в scratchpad, то есть профиль свежий на каждый вызов, и `localStorage`,
выставленный кликами в браузере пользователя, ему не виден. Какие ключи и в каком формате
держит приложение — `memory/commands/frontend.md`. Рабочий порядок: открыть origin, записать
значения через `Runtime.evaluate`, затем навигироваться на целевую страницу. Побочная выгода:
так состояние ставится без кликов, то есть без гонки повторных нажатий.

**Постраничная подгрузка свежей навигацией не воспроизводится.** «Показать ещё» и кнопки
страниц сбрасываются — всегда приходит первая страница, и товар, лежащий на третьей,
скриншотом не снимается вовсе. Такой пункт отмечается непроверенным и подтверждается текстом
страницы, а не выдаётся за скриншот.

**Каждый снятый скриншот надо открыть через `Read` и описать.** `Read` рендерит изображение;
скриншот, который никто не смотрел, приёмку не закрывает — на то он и visual check. В отчёте
перечисляются имена файлов, которые действительно открывались.
