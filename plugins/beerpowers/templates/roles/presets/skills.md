# Каталог поводов для скилов ролей

> Источник для слота `SKILLS_GUIDE` шаблонов `templates/roles/*.md` и для поля `skills:`
> их frontmatter. setup вписывает в `skills:` только скилы, которые нашлись в сессии:
> отсутствующий обязательный скилл ломает старт роли. Для каждого вписанного скила
> в слот `SKILLS_GUIDE` роли идёт его строка из таблицы ниже (у ролей с таблицей) или абзац
> (у `architect`, `db`, `reviewer`). Скилы другого плагина пишутся в `skills:` полным именем
> (`superpowers:test-driven-development`), если найдены в сессии. Скилы самого beerpowers
> (`beerpowers:page-screenshot` и другие) в `skills:` не пишутся: они есть в любой сессии с плагином,
> роль зовёт их по имени через `Skill`, а charter называет их в «Mandatory practices».
> Их строки таблицы идут только в `SKILLS_GUIDE`.
>
> Встроенный `security-review` в `skills:` не вписывается никогда: при сборке промпта роли
> он выполняет `git diff` от рабочего каталога, а не от репозитория задачи, и роль падает
> на старте или смотрит не тот дифф. Его работу у `reviewer` и `auditor` делает ручной
> security-чеклист шаблона.

## Строки таблицы «Скилл | Когда звать»

| Скилл | Роль | Когда звать |
|---|---|---|
| `laravel-specialist` | `backend` | очереди и Horizon, Sanctum и политики доступа, сложные связи Eloquent, API-ресурсы, Livewire |
| `php-pro` | `backend` | типизация под PHPStan, value object и DTO, возможности PHP 8.x, async-паттерны |
| `nuxt` | `front` | SSR и гидратация, server routes, middleware, `useFetch`/`useAsyncData`, гибридный рендер, автоимпорты |
| `nuxt-ui` | `front` | новый компонент из библиотеки, тема и токены, слоты, формы на @nuxt/ui |
| `karpathy-guidelines` | `backend`, `front` | постановка допускает несколько прочтений или у задачи нет критерия готовности: назвать допущения вслух и превратить задачу в проверяемую цель. Объём решения — не его, это `beerpowers:minimal-diff` |
| `beerpowers:page-screenshot` | `front` | любой скриншот файлом: self-check, скриншот для отчёта, замер прокрутки и вычисленных стилей через CDP |

## Абзацы

### `karpathy-guidelines` — `architect`

Скилл `karpathy-guidelines` зови, когда постановка допускает несколько прочтений или
у задачи нет критерия готовности: он требует назвать допущения вслух вместо молчаливого
выбора и превратить задачу в проверяемую цель. За объём решения отвечает `beerpowers:minimal-diff`,
дублировать его незачем.

### `db` — Laravel

`laravel-specialist` — сложные связи Eloquent, кастомные касты, Scout и индексы поиска;
`php-pro` — типизация каста или value object под PHPStan.

### `reviewer`

`caveman-review` — оформление замечаний в отчёте; `karpathy-guidelines` — у задачи не видно
критерия готовности либо исполнитель выбрал одно из нескольких прочтений постановки молча,
не назвав допущение.
