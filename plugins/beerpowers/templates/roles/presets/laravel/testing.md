## PHPUnit — прогон

Рабочую форму прогона бери из `memory/commands/<скоуп>.md`: она может зависеть от того,
поднят ли контейнер приложения. Тесты идут по реальной БД в отдельной тестовой базе
(`memory/tests/backend.md`), конвенции — по соседним файлам сьюта.

Что покрывать на бэке: Application Services и доменные сервисы модулей — Unit; эндпоинты
API — Feature; интеграции с внешними системами (хранилище файлов, поиск) — Integration.
Денежная арифметика и каст денег покрываются всегда, это money-critical зона.

**Зелёный PHPUnit — не весь гейт.** Написал или правил тестовый файл — прогони по нему
статический анализ, отдельной командой, и добейся нуля ошибок в своих файлах:

```bash
vendor/bin/phpstan analyse <путь к тесту> --memory-limit 2G --no-progress
```

(в контейнере приложения — форма из `memory/commands/<скоуп>.md`). Если `phpstan.neon`
берёт и `app`, и `tests`, а CI анализирует только `app`, красноту в тестах пайплайн
не покажет — поймать её можешь только ты. Критерий — ноль ошибок в файлах, которые правил
сам, и ноль новых вне них. Чужая краснота — запись в `memory/tests/backend.md`
или `memory/tech-debt/`, с которой поступаешь по charter, «Записи о красных базах…»; всё
остальное — твоё.

Типовая ловушка: `$response->json('data')` возвращает `mixed`, поэтому `$data[0]['id']`
даёт `Cannot access offset on mixed`. Конвенция — `assertArrayHasKey` перед обращением;
в цикле с переменным ключом это не сужает тип, там элемент достаётся отдельной переменной
под `assertIsArray`. Образцы — в `memory/tests/backend.md`.
