# Пресет: Laravel → architect

> Фрагменты для слотов `templates/roles/architect-agent.md`, когда бэкенд проекта — Laravel
> с модульной раскладкой (`app/Modules/*`, `app/Application/*`, `app/Infrastructure/*`).
> setup вставляет раздел в слот с тем же именем; после вставки это проектный текст — сверь
> имена каталогов и модулей с репозиторием. `<Namespace>` — корневой namespace проекта.

## Слот `ROLE_CONTEXT`

секреты и привилегированные операции живут в серверном слое Laravel, целостность данных —
в схеме БД и Application Services.

## Слот `DESIGN_FIRST_QUESTION`

2. **Первый вопрос любого дизайна: в каком модуле это живёт и кто с кем говорит?**
   Каждая новая сущность обязана ответить: чей это модуль (список модулей —
   `memory/project/project-map.md`), нужна ли кросс-модульная связь и почему её нельзя
   избежать, какая схема БД, какие импорты между модулями появятся (греп: `deptrac`
   доказывает границу только для слоёв, описанных в его конфиге).

## Слот `LAYER_CANON`

   - Целостность данных и уникальность → ограничения и индексы БД (`db`), не проверки в коде.
   - Бизнес-логика модуля → `app/Modules/<Модуль>/Services/*` (`backend`).
   - Координация между модулями → **только** `app/Application/Services/*` (`backend`).
     Модуль не зовёт модуль напрямую. Если машинная граница (`deptrac`) покрывает не все
     модули, кросс-модульные импорты проверяются грепом.
   - HTTP-вход → `app/Application/Http/Controllers/Api/**` (action-классы) + Request-валидация.
   - Внешние системы (S3, поиск, почта, мониторинг) → `app/Infrastructure/*` за интерфейсом.

## Слот `REVIEW_SMELLS`

```
[ ] Модуль зовёт другой модуль напрямую в обход Application Services (deptrac ловит
    только слои из своего конфига — остальное грепом по `use <Namespace>\Modules\`)
[ ] Контроллер зовёт доменный сервис модуля минуя Application Service
[ ] Деньги как float/decimal где-либо вместо каста денег проекта
```

## Слот `CONSULT_TEST`

Типовой тест: целостность данных → ограничение БД; логика одного модуля → сервис модуля;
координация модулей → Application Service; работа с S3/поиском/почтой → Infrastructure за
интерфейсом; отображение → composable + компонент.
