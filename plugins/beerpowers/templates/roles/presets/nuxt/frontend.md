# Пресет: Nuxt → front

> Фрагменты для слотов `templates/roles/frontend-agent.md`, когда фронтенд проекта —
> Nuxt 3/4 + Vue 3 + TypeScript. Строки про сгенерированный клиент API — только если клиент
> генерируется из схемы бэкенда (orval или аналог); строки про `@vueuse/core` — если он стоит
> в `package.json`. `<каталог фронтенда>` — путь к репозиторию фронтенда от корня workspace.
> Конвенции именования, стилей, брейкпоинтов, слоя данных и языка UI у каждого проекта свои:
> их setup пишет в проектную часть роли по факту репозитория, пресет их не задаёт.

## Слот `FRONTEND_CONFIG`

`nuxt.config.ts`

## Слот `ROLE_SCOPE`

`app/pages`, `app/components`, `app/composables`, `app/stores`, `app/layouts`, `app/types`,
`app/assets`, `server/` (Nitro-роуты), `plugins/`.

## Слот `HARD_RULES`

- **Типы API — только из сгенерированного клиента** (`app/api/model/`). Локальных дублей
  типов ответов не заводим.
- **Props и emits** — через `defineProps<T>()` / `defineEmits<T>()`.
- **Composables** лежат в `app/composables/**` и автоимпортируются (`imports.dirs`).
- **SSR по умолчанию.** CSR только там, где через SSR нельзя (`window`, размеры вьюпорта,
  геолокация), и выбор обосновывается. `{ server: false }` в новом коде — повод объяснить,
  а не скопировать у соседа.
- **Новое — на `<script setup lang="ts">`.** Легаси переписываем в рамках задачи, не попутно.
- **DOM-обвязки — через `@vueuse/core`**, свои composable под готовое не пишем.
- **Конфиг и ключи — только `runtimeConfig`** из `nuxt.config.ts`.

## Слот `NATIVE_TOOLS_EXAMPLES`

Ступень, главная для этого слоя: у проекта богатый набор модулей (перечисли установленные
модули Nuxt и библиотеки форм из `package.json`) — своя реализация того, что они дают,
разбирается на ревью объёма, как и абстракция под один вызов или копия существующей
fetch-логики.

## Слот `GATE_NOTES`

Если отдельного скрипта `typecheck` в `package.json` нет, типы проверяются внутри `build`
(`typescript.typeCheck` в `nuxt.config.ts`). Тогда критерий типов — ноль строк `error TS`
в полном логе `build` (код выхода — charter, «Число в отчёте…»). Перед прогоном — `nuxt prepare`
(`run postinstall`): устаревший `.nuxt` даёт ложные `TS2304`.

Линт (charter, «Линт в конце задачи») — через скрипт пакета
(`npm --prefix <каталог фронтенда> run lintfix -- <файлы>`, пути относительно каталога
фронтенда): прямой `npx eslint` из корня workspace файл может молча не проверить.
