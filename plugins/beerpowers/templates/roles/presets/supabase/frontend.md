# Пресет: Supabase → front

> Фрагменты для слотов `templates/roles/frontend-agent.md`, когда клиент ходит в
> Supabase/Postgres напрямую под политиками доступа (RLS), а привилегированные операции —
> через серверные routes. Строки про scope-канон и realtime — только если они есть в проекте.

## Слот `ROLE_SCOPE`

Данные — напрямую через клиентский запрос из composables (политики доступа режут видимость
сами); привилегированные операции — вызов существующих серверных routes (сами routes —
зона `db`/architect). Политики доступа не трогаешь.

## Слот `HARD_RULES`

- **Типы только из единого источника типов проекта.** Никаких локальных дублей row-типов.
  Изменилась схема → сначала типы (синхронно со схемой в `memory/`), потом код.
- **Scope-зависимый кэш — канон проекта (три шага):** (1) состояние с уникальным ключом,

  Пропустил любой шаг — данные «протекут» между scope.

  отдавать id не в очевидном поле — повторяй принятый в проекте фолбэк).
