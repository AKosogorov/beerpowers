# 🛣️ Roadmap

Практики, отложенные до триггера. У каждой — условие, при котором она окупится, и описание,
достаточное для внедрения. Сработал триггер — практика переносится в шаблон charter,
`team-lead.md` или хук, пункт отсюда уходит в `CHANGELOG.md`. Порядковых знаков у пунктов
нет: пункты уходят, и номер или буква начали бы указывать не туда. Ссылка на пункт — по его
заголовку.

## Чеклист состояния задачи для рестарта сессии

**Триггер.** Обрыв сессии посреди задачи (лимит, `/compact`, новая сессия по той же задаче),
после которого пересборка контекста заняла заметное время или пошла из устаревшего состояния.

**Форма.** Файл `progress.md` в папке задачи — закрытый список артефактов расширяется на один
пункт. Не свободный журнал, а таблица этапов, предзаполненная по классу задачи (для фичи:
dry-run → design brief → срезы исполнителей → ранний `reviewer` → `tester` → финальный
`reviewer` → закрытие), с колонками «факт · коммит · гейт → итог · дата», которые заполняются
на границе каждого этапа в том же вызове, что коммит. Последняя строка — закрытие. Внеплановое
дописывается строками между этапами: рекласс, ребейз («база такая → такая, гейты перегнаны»),
схлопывание, запрос ревью («история заморожена»), решение team-lead'а в форме «что — почему —
цена ошибки». Перезаписываются две строки: «Дальше» и «Читать первым».

**Доказательство — в строке, не в коммите.** Команда гейта и её итог пишутся дословно; коммит
обозначается темой `type(<КОД>): суть`, которая переживает ребейз, хеш — только примета момента.

**Разграничение.** `plan-delta.md` — отступления реализации от утверждённого дизайна, ведёт
`architect`; «решение» в `progress.md` — выбор team-lead'а по ходу. При `/beerpowers:retro`
решения, пережившие задачу, уходят в `issues/known-issues.md` или charter, файл удаляется
с папкой. Скрипт, пишущий строку только при зелёном гейте, — после двух-трёх задач руками,
когда форма строки устоится.

## `SubagentStop` сверяет заявленный прогон с транскриптом

**Триггер.** Роль отрапортовала «зелёный», «прошли», «без ошибок», а в её транскрипте вызова
соответствующей команды нет.

**Форма.** Хук читает `last_assistant_message` и `transcript_path` из входа события.
Срабатывает только на утверждении о **результате** (зелёные, прошли, passed, без ошибок,
0 failures), не на упоминании темы: на топик-триггере почти все срабатывания ложные. Пары
«предмет → искомая команда» — из параметров стека проекта (тесты → раннер тестов; гейты и типы →
статанализ, typecheck, сборка). Нет команды в транскрипте — вернуть агенту текст через
`hookSpecificOutput.additionalContext`, не `exit 2`: на этом событии он подменяет роли задачу
текстом из stderr. Один возврат за сессию на агента (маркер-файл в `$TMPDIR`), иначе роль,
не способная закрыть гейт, крутится до конца сессии. Читающие роли (`explorer`) исключить
по `agent_type`: они цитируют чужие числа.

**Цена.** Хук действует на все сессии и вступает со следующей; `jq` на Windows может
отсутствовать — писать на `sed`, как `quality-reminder.sh`. Перед доверием — инъекция заведомо
ложного отчёта и подтверждение поимки.

## Кап параллельных opus-заходов

**Триггер.** Групповой обвал: несколько ролей на opus легли одновременно на лимит сессии,
и работа каждой пропала без частичного сохранения.

**Форма.** Не больше двух-трёх ролей на opus одновременно, остальные волнами по мере возврата;
перед широкой раздачей проверить, нет ли второй сессии с параллельной раздачей на той же квоте.
Падение части пачки — переспавн только упавших, восстановление по имени через `SendMessage`,
не новым вызовом. Падение роли не означает «находок нет»: в вердикт идёт как непроверенное.

## Контракт-линза как режим `architect`

**Триггер.** Парная бэк-фронт задача с новым или изменённым эндпоинтом, которым пользуется
фронт, и расхождение формата, которое генерируемые типы не ловят.

**Форма.** Режим `architect`, не новая роль, до кода: по каждому эндпоинту — потребитель,
конверт ответа и пагинация с потолком `limit`, различимость кодов ошибок (один код не означает
два противоположных отказа) и параметры для подсветки поля формы, данные под действия UI
(кнопка «Удалить» получает счётчик зависимостей, а не сюрприз 409), симметрия `POST`/`PATCH`
на одном теле, что сломается в очевидной следующей задаче. Конвенция устанавливается счётом
прецедентов грепом, не вкусом; «потребителю не хватает X» без постановки или слов потребителя —
гипотеза, вопросом. Результат — раздел design brief; финальный `reviewer` сверяет реализацию
с ним.

## Ранний адверсариал на деньгах и конкурентности

**Триггер.** Задача, в которой деньги участвуют в арифметике или есть конкурентные записи,
а не только отображение цены.

**Форма.** Первый заход независимого оппонента (claude-adversary через team-lead) — в момент,
когда впервые заработал сквозной путь, фоном и read-only, не дожидаясь финального ревью;
финальный заход остаётся. Поздний единственный адверсариал находит денежный баг ценой
рефакторинга уже готовых слайсов. Проверка каждой денежной ветки — мутацией прод-кода
с показанным диффом и откатом, как в практике `tester`'а.

## `tracker:write` для QA-чеклиста

**Триггер.** QA-чеклист `<КОД>-qa.html` стабильно выкладывается в трекер руками и это заметная
доля закрытия задачи.

**Форма.** Подкоманда `yandex-tracker` с правом записи: прикрепить файл чеклиста к задаче
трекера. Сейчас чеклист выкладывает человек — запись в трекер внешняя и видна заказчику,
поэтому форма вызова и подтверждение перед записью проектируются отдельно.

## Комментарии — проверка у автора на выходе роли

**Триггер.** Комментарий-пересказ снова дошёл до MR, хотя `reviewer` проверяет комментарии
блокером (чеклист «Комментарии в диффе»), а `guard-comments` ловит `#`, хвостовые комментарии
и `commit -a`.

**Форма.** Хук `SubagentStop` по образцу `screenshots-reminder.sh`: один раз на `agent_id`, если
в диффе роли есть добавленные строки комментариев, — `exit 2` со списком строк и требованием
решить по каждой. Сейчас добавленные комментарии видит team-lead на коммите, а не автор:
к коммиту роль уже закончила, и team-lead повторяет команду, не перечитывая чужой код. Цена —
лишний ход каждой роли, оставившей комментарии; `exit 2` подменяет роли задачу текстом
из stderr (`reference/runtime-compat.md`), поэтому текст должен быть выполнимым действием.

## Барьер тестовой базы перед прогоном тестов

**Триггер.** Второй проект, где полный прогон тестов бэкенда упал тысячами ошибок
`database does not exist` или `relation does not exist`: тестовую базу снесла чистка Docker
или новое рабочее дерево пришло без неё, и красный прогон прочитали как красный код.
Первый такой проект закрыл это проектным хуком и скриптом проверки; правило прозой
«проверь базу перед прогоном» до этого не сработало.

**Форма.** Барьер плагина на `Bash` с флагом в `barriers`: команда совпала с шаблоном прогона
тестов из `workspace.json` (например `phpunit`, `artisan test`) и называет каталог
репозитория в `projects/` или `worktrees/*/` — хук зовёт проектный скрипт
`.claude/bin/testdb-check <каталог>`. Код 1 — deny с причиной и формой лечения, код 2
(не смогли проверить: нет Docker, не тот каталог) — пропуск. Механика базы — имя из
`.env.testing`, контейнер, пользователь, миграции — остаётся в проектном скрипте: она у каждого
стека своя. Сам вызов проверки и её лечения хук не останавливает.

## Другие профили git

**Триггер.** Проект, флоу которого раз за разом описывается как `custom` одними и теми же словами.

**Форма.** Профиль в `reference/git-flow.md` и в `lib/git.mjs` рядом с `main-default`
и `dev-default`. Кандидаты: trunk-based без релизных веток; GitLab Flow с ветками окружений
(`main` → `pre-production` → `production`, merge только вниз); ветки сопровождения — правка
сначала в основной, затем `cherry-pick -x` в релиз.
